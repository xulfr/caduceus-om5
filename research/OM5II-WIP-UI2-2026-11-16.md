# OM-5 Mark II WIP UI candidate 2 (16 November 2026)

**Emulator only.** Nothing below has run on a camera. The previous candidate (`ae96e94`, package
`7ba9aba0…b92508`) is the camera-tested baseline for the icon and Live ND label fixes it carries.
Addresses are runtime addresses of the expanded E148 1.1 main program.

## HSL axis does not repaint (trash on the colour wheel)

Camera: Saturation → Hue repainted, further presses left the title on Hue until the user scrolled away.

- The axis switch (`hsl_container`) refreshes the editor's enum children and sends `0x900c` to the focused
  child. Nothing invalidates the colour page's view, whose paint (`paint_axis`) draws the title.
- A watch on the window's dirty-layer flags (`0x60d45d1b`, `0x60d45d5d` in `0x60d45cd6`) shows **no** dirty
  mark during a baseline trash press. OM-Emu still repaints because its flush posts `0x1002` for the whole
  plane; that is why the defect never showed in the emulator.
- Fix: the switch sets `P+56`; `pages_hook` (run by the panel update that follows the consumed press)
  invalidates child 4, the colour page, with OM's widget invalidate `0x60d49294` (`d0 = 1`, `a1 = 0`, the
  same call a label makes at `0x60d8df09`). The fixed build adds exactly one dirty mark per press.

## Screen times out during custom controls

- The direct-setting screen closes when GUI timer 500 expires. The stock container restarts it with
  `0x60f10fd2(500, 8000)` only when a child consumed the command and the container's `+92` is 1
  (`0x60e3ca89..0x60e3ca9b`, and `0x60e3c7ce..0x60e3c7de` for direction keys and dials).
- The axis switch and the film step are consumed in project code, and INFO (`0x9014`) on the custom pages goes
  through a stock branch without a restart. OM-Emu reproduced the timeout for trash on the wheel and the
  mode strip and for INFO on the wheel and tone rows; dials and arrows already kept the screen open.
- Fix: `ui_activity` (section 10, armed only) makes the same restart for the axis switch, a film step and a
  consumed INFO on the screen's own container with a Color or Monochrome Profile selected. The timer value,
  the screen and every other path are stock. An idle screen still closes after about 8 s.

## Tone Curve sidebar icon

The row asks for image `0x38cc` (map entry at `0x611b4b5c`, value `0x92`), an empty placeholder in E148.
It is aliased to the stock neutral tone-curve glyph `0x2aef` (28 × 28, one of E148's Highlight & Shadow
icons). The sidebar centres it in the row, selected and unselected. `tools/oly_resource_recipe.py` re-encodes
record 0 from the current recipe's own stream; only that pointer word changes (11 more packed bytes, length
rule passes), and `tests/audit_build.py` now checks that nothing else in the resource block changed.

## ND32 and ND64 missing from CP Button Settings

- Page `0x16f` (gear menu, CP Button Settings) copies its item IDs from the page table entry at `0x611943a4`:
  list `0x61193dc0`, 10 IDs (2211..2216, 2224..2227). The item records at `0x611d0c6c` (stride 28), the CP item
  tables `0x60f7f584` and `0x6118fe7c`, and the carousel's jump table `0x61190d70` all include 2217
  (ND32) and 2218 (ND64); 2217/2218 share the ND case `0x60e27f92` with 2213..2216.
- Settings 2217 / 2218 have cells (both read 1) but no descriptor among OM's 1589 static descriptors
  (`0x6050dad4`). The writer (`0x602d0f23` → `0x602e1a33`) finds none and drops the change.
- Fix: data edits put a 12-item list (ND32, ND64 after ND16) and two stock-format copies of 2216's descriptor
  in the record copies color_profiles.py already frees (`0x604f24d8..0x604f2518`), and repoint page `0x16f`.
  After arming, `cp_nd_link` links the two descriptors into OM's RAM descriptor hash (128 buckets at
  `0x620dc288`, chain node `{descriptor, next}`) with nodes in the heap state block (`P+988..1003`). No boot
  code, image byte or stock RAM array is resized.
- OM-Emu: both items appear and scroll; each toggles independently after arming and toggles back; ND16 is
  unaffected. Before the first half-press a toggle of ND32/ND64 is dropped (no descriptor yet).
- Not verified: the CP-button carousel. The CP button is not wired in OM-Emu for E148. The carousel code
  handles 2217/2218 natively, but which list gates its entries is unconfirmed.

## Colour wheel and tone curve graphics: unresolved

No new progress beyond the alpha8 handover trace. OM-Emu has no C3D/OpenVG layer, so the graphics cannot be

## ND64 label artefact (P3): cause identified, not changed

The ND64 prefix is composed artwork (`resource_aliases` sprite `0x205d`): `ND` from `0x2060`, then the `6` and
`4` digit crops (`0x2060` columns 39..56 and `0x205e` columns 40..56) narrowed to 13 px each by nearest-column
sampling (`oly_ui_bitmap.append_icons`, `width`). Dropping columns from 17/16 px glyphs is the likely source of
the artefact on the digits. A cleaner version needs narrower stock digits or a crop without resampling; it
changes the bitmap record and its LZ4 recipe, so it was left for a later cycle as low priority.
