# OM-5 Mark II WIP UI candidate 3: colour wheel and tone curve (16 November 2026)

**Emulator only.** Nothing below has run on a camera. Addresses are runtime addresses of the expanded
E148 1.1 / E147 1.1 main programs (base `0x60021020`).

## Why the graphics were missing (static comparison, verified)

- OM-3 (E147) draws both through its GPU layer. Its page controller (`0x61135657..0x6113569d` and
  `0x61135725..0x6113576a`) calls `guiUtility::chgBackGround DRAW_PROFILE` (`0x612981c8`, debug string
  `0x615fc73b`) with background id `0xffec`, which E147's table `0x615fc76c` maps to various-draw type 11,
  `VARIOUS_DRAW_PROFILE`; the argument 6 / 7 selects the graphic.
- E148 has neither. Its controller (`0x60dad445..0x60dad468`) only sends `0xfffd`; its table `0x6125fdf0`
  has no `0xffec` and ends at types 10 / 11 `SCN_TOP` / `SS_MENU`; no `DRAW_PROFILE` string or function exists
  and the C3D type list (`0x60b93874..`) has no `PROFILE`. `chgBackGround` itself is `0x60f1175d`.
- The profile wheel view (`0x610c14a0`, data block 15) makes no draw request on either model; the views that do
  (`0x60df1605` block 278, `0x60dfaf61` block 279) are Color Creator and Partial Color.
- Conclusion: the restored pages have no native graphic to request on E148. Not tried: E148's
  `VARIOUS_DRAW_COLOR_CREATOR2` (type 6), which has no background id and cannot be observed in OM-Emu.

## What the candidate draws instead (CPU, OSD plane)

- OM's pen in a paint context: `pen_color 0x60d51e2c` (context +36), `pen_size 0x60d51eed` (+40/+42),
  `move_to 0x60d519e7` (+32), `line_to 0x60d51774`; style +48 (0 solid). The colour is an index into the
  screen's 128-entry palette (indices 128..255 repeat it; a probe build drew all 256).
- The pen is centred on the line across its thickness; a zero-length line ignores the pen.
- **Negative result:** slanted lines cost one OSD command per pixel. The driver's command buffer
  (`0x60cc647f`, called from `0x60cc5dc6`) ran out after about 1050 pixels in one repaint and the rest was
  dropped (two 12-sided rings drew, the third and all spokes did not). Level and plumb lines are one command.
  Everything is therefore drawn as axis-aligned blocks (wheel at most about 240 commands, curve about 75).
- Wheel (`gfx_wheel`, section 5, called from `paint_axis`): centre (290, 222), value 0 at radius 84, 8 px per
  step, Yellow at the top, clockwise. Per colour: scale dots -5..+5, a bar of blocks from 0 to the value on the
  active axis (`ui_read`), an 11 px block at the value, a white edge on the selected colour (editor +122:
  1..12, 0 = all). The editor is `(*scr_obj)->+0 ->+76`, checked as `hsl_container` does. Palette indices
  123, 92, 16, 122, 89, 88, 87, 105, 107, 86, 22, 116; white 13, grey 12.
- Tone curve (`paint_tone` in section 6 on the tone view's paint slot `0x610d6600`, stock `0x60d47232`;
  `gfx_tone` in section 10): 192 px box at (194, 104) with a quarter grid and dotted diagonal; 48 columns bent by
  Shadows / Midtones / Highlights (`stock_get` of 976+3p.. or 1021+3p.., stored H, M, S) with raised-cosine
  bumps centred on columns 12 / 24 / 36, 4 px per step at the peak.
- Repaint: OM invalidates only the label that changed, so a stale wheel stayed on screen in OM-Emu too.
  `pg_axis` now invalidates the shown page (flag +245 colour → child 4, +247 tone → child 2) on every panel
  layout. One layout per consumed command was counted (14 for 14 effective inputs). `P+56` is no longer used.
- E148's own swatch has six colours for the twelve sectors (styles change every second colour); unchanged.
